# CPU-only observed experience pilot, frozen before implementation
One observer, two anonymous motor codes. Learn movement correspondence from self-observed motion and an external outcome readout from paired visible changes and own body changes in calibration. Never train self-outcome counts on demonstrations. Give consistent, reversed, or no demonstrations, with identical calibration, fallback choices and outcome noise per seed (200 independent seeds 32000..32199). Reversal means the demonstrator and learner have opposite wiring. Freeze an additional same-body switch after 16 own opportunities. The learner receives only observable vectors, its own executed code and its own measured deficit change at event closure. No actor action ID, correct side, or wiring enters a demonstration. Synthetic synchronized event boundaries and common visual frame are assumptions.
Primary gates: correct first press >=80% after valid demonstration and >=20 percentage points above no demonstrations; before contact own-known exactly zero; with misleading demonstrations median time to four consecutive correct presses at most one press slower than baseline, both on first wiring and after switch. Report failures/censored cases, 90th percentile, false demonstrations, ambiguous motion and unseen appearance as stress conditions. Report CPU device, byte count, latency, direct contacts. Physical joules only from a measured counter. This is a prototype alongside the three scenes; no use of GPU or upstream default changes.
